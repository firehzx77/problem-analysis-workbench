# 三生 · AI 赋能问题分析解决 — 产品功能规划

## 1. 产品结构

产品中心对象是**课题（Case）**，不是会话。一次会话只是某一步的工作方式；课题档案才是主数据。

```
工作扫描 / 问题雷达
        ↓ 选定 1 个信号
   选题与问题定义  ── Gate 1
        ↓
   问题分解与系统分析  ── Gate 2
        ↓
   设定关键目标
        ↓
   路线分流：行动试验 A  /  原因探索 B
        ↓
   对策创造 → 红队评估  ── Gate 3
        ↓
   最小实验 → 实施检查点
        ↓
   复盘与固化 → 课题档案 / 案例库
```

控制圈 / 影响圈 / 关注圈贯穿选题与分解：默认只把**控制圈 + 可推动的影响圈**做成行动项。

## 2. 八步模块与功能要点

### 步骤一｜明确问题

**学员动作**

- 粘贴日报、投诉、经营数据、项目记录、会议纪要、质量异常
- 用“我又”项做工作扫描（又要做 / 又错了），并用 4E 粗评：简单、高效、可测、经济
- 将候选事项放入影响 × 行动矩阵，只保留最多 3 个优先焦点
- 自己定义选题：场景 / 任务（自由文本）、现状值、期望值、一句话描述、核心词定义。不填岗位，不从岗位模板里选。

**系统能力**

- **AI 问题雷达**：只基于材料扫描明显异常、趋势、重复事件、弱信号；先指出信息缺口；按“信号—证据—频率—影响—趋势—建议优先级”输出机会池
- **AI 问题定义教练**：禁止分析原因；逐句标记事实 / 解释 / 判断 / 假设 / 情绪；用 BAIDU（背景 B、现状 A、影响 I、已行动 D、期望 U）补齐；输出标准问题陈述与边界
- 三圈分类板、差距陈述公式（对象 / 时间地点 / 现状 A / 期望 B / 差距 / 影响）
- 问题类型标记：恢复原状 / 防范潜在 / 追求理想；发生型 / 设定型

**Gate 1（学员自检）**：对照清单确认问题是否数据化、对象化、边界化，并写下判断依据。未通过不得进入原因分析；系统可提示缺口，但不代勾、不代过。

### 步骤二｜分解问题

**学员动作**

- 把“看到的”和“想到的”分开
- 选择切分维度并检查 MECE（每层一个标准类型）
- 选择树的类型：问题树（分析什么）/ 原因树（为什么）/ 方案树（可以怎么做）
- 为假设列出：验证方法、所需数据、数据来源

**系统能力**

- **AI 系统分析师**，固定三层：
  1. 拆：3–6 个 MECE 维度，建问题树，找问题集中区
  2. 追：3–5 个竞争性原因假设，不把相关当因果；每项含支持证据、反证、缺失证据、最低成本验证动作
  3. 连：关键变量、增强回路 R、平衡回路 B、延迟、二阶影响、杠杆点
- 漏斗视图：大量信息 → 建立结构 → 验证判断 → 寻找杠杆
- 冰山标记：事实进陈述，解释留视角，假设进验证清单
- 路线分流卡：原因已清、试错便宜 → 路线 A；原因冲突、反复发生、错了代价大 → 路线 B

**Gate 2（学员自检）**：优先原因是否同时具备支持证据、反证检查、验证动作？通过时写依据。

### 步骤三｜设定关键性问题目标

**学员动作**

- 把目标写成“到什么时候、解决到什么程度”
- 避免把行动、手段、理想状态写成目标

**系统能力**

- 目标检查器：是否定量、是否有期限、是否针对问题点、是否可验证
- 自动拦截抽象词（努力提高、彻底、妥善）和“把手段当目标”
- 输出：基线、目标值、期限、领先指标 / 结果指标 / 护栏指标

### 步骤四｜把握真因

**学员动作**

- 在线性、可现场验证的问题上做带证据的 5WHY
- 多因素问题先展开原因树，再对关键分支追深
- 用鱼骨（人机料法环测，或流程步骤）做脑力激荡，再排序筛选

**系统能力**

- 5WHY 编辑器：每一层必须挂证据；停止条件是“可观察、可验证、团队有权改变的流程机制”
- 禁止结束语库：员工责任心不强、沟通不到位、管理需要加强、缺乏培训、新员工
- 黑白思维 vs 概率思维提示：对竞争性原因给置信度，而不是宣布唯一真相
- 鱼骨图构建向导与逻辑检查（正向为什么 / 反向引起）

本期不做完整统计引擎（回归、ANOVA、卡方）；只保留“需要什么数据、用什么检验思路”的引导，避免做成伪六西格玛软件。

### 步骤五｜制定对策

**学员动作**

- 先填：现有任务 / 普通方案、改善目标、必须约束、可利用资源
- 用 5W 选变化焦点，用 SCAMPER 做 2–3 个变换动作
- 先发散至少一批候选想法，再做目标 × 约束双检验
- 用 3×3×3 法则：先过必须条件（假设 / 红线），再对需求加权打分，并做负面评价

**系统能力**

- **AI 创新对策引导师**：只扩展方案空间，不替人决策；信息不足最多 3 个澄清问题
- **AI 红队**：从成本、时间、人员、流程、技术、利益相关者、合规、二阶影响攻击；Pre-mortem 推演失败链；区分可逆 / 不可逆；区分事实评分与假设评分
- 5W × SCAMPER 画布与候选想法表

**Gate 3（学员自检）**：风险可接受吗？关键假设能否先验证？由学员本人拍板并写下依据。

### 步骤六｜贯彻实施对策

**学员动作**

- 把大方案改成 5W2H 计划：谁、做什么、何时、何地、为何、如何、费用
- 设置中间检查点、汇报节奏、障碍升级规则

**系统能力**

- **AI 行动实验设计师**：输出假设—实验—证据闭环
  - 核心假设（如果做 X，Y 如何变）
  - 最小实验（对象、范围、周期、动作）
  - 基线与三类指标
  - 成功 / 停止 / 扩大标准
  - 责任人、检查点、记录方式
  - 可能污染结果的变量
- 实验卡默认约束：2 周内出信号，失败可恢复
- 轻量检查点清单（不做重型项目管理）

### 步骤七｜评价结果和过程

**学员动作**

- 对照目标看结果：达成 / 超过 / 未达成，以及新增与消失的现象
- 区分结果偏差与执行偏差

**系统能力**

- 结果对照表：目标、实际、偏差、是执行问题还是假设问题
- 过程评价：哪些步骤被跳过、哪些闸门是补做的

### 步骤八｜巩固成果

**学员动作**

- 决定什么进入 SOP / 检查表 / 案例库，什么还要继续实验
- 识别横向推广边界，并写下下一轮改善点

**系统能力**

- **AI 复盘教练**：对照“原始问题—原因假设—方案假设—实际行动—实际结果”
  - 找出被证实、被推翻、仍未知的假设
  - 识别关键事件，避免事后合理化
  - 提炼经验、适用边界、可迁移规律
  - 建议沉淀物，并给出 3 个反思问题
- 固化三件套：标准化、横向展开、下一步改善

## 3. 七个 AI 角色（系统内置人格）

| 角色 | 对应步骤 | 允许做 | 禁止做 |
| --- | --- | --- | --- |
| AI 问题雷达 | 明确问题 / 扫描 | 找信号、标缺口、排优先级 | 推测原因、给解决方案 |
| 问题定义教练 | 明确问题 / 选题 | 分类语句、补 BAIDU、写标准陈述 | 分析原因 |
| 系统分析师 | 分解问题 | 建树、竞争性假设、回路与杠杆 | 把相关当因果、假装证据充足 |
| 创新对策引导师 | 制定对策 | 5W × SCAMPER 发散、双检验 | 给唯一答案、替人决策 |
| AI 红队 | 制定对策 / 决策 | 攻击方案、失败链、降风险修改 | 为方案辩护、隐瞒不可逆风险 |
| 行动实验设计师 | 实施 | 把方案写成最小实验 | 规划无法停止的大项目 |
| AI 复盘教练 | 评价 / 巩固 | 假设对照、经验边界、组织知识 | 只写总结腔、夸大因果 |

所有角色共用三条底线：不编造数据；推断必须标置信度；信息不足先问、后做。

## 4. 课题档案（主数据）

一份课题至少包含：

- 元信息：学员自定标题、场景 / 任务、问题类型、当前步骤、闸门自检记录（依据文本 + 时间）
- 原始材料与机会池
- 标准问题陈述、BAIDU、边界与暂不讨论项
- 三圈分类、焦点评分
- 问题树 / 原因树 / 方案树
- 证据表（已知 / 未知 / 假设）
- 目标与指标口径
- 路线选择（A / B）及理由
- 候选对策、红队结论、加权矩阵
- 实验卡与检查点记录
- 复盘：被证实 / 被推翻 / 仍未知；沉淀建议

导出格式（一期）：Markdown / PDF。二期增加 A3 一页纸、8D 表、DMAIC 阶段卡。

## 5. 设置与本地数据（一期必做）

无注册、无登录。打开网页即可用。

**设置页（学员自配模型）**

- 提供商 / 兼容协议（OpenAI 兼容即可覆盖多数网关）
- API Base URL、模型名、API Key
- 可选：温度等生成参数
- Key 与配置只存在本机浏览器，不上传到本产品服务器
- 未配置完整时，允许浏览步骤和填写结构，但调用 AI 角色时拦截并引导去设置

**课题存放**

- 课题档案存在本机（localStorage / IndexedDB）
- 支持整份课题导入 / 导出（JSON + Markdown / PDF），换设备靠导出文件，不靠账号同步

## 6. 后期可选，不是一期

- 讲师班级看板、课堂任务分发
- 同一课题导出为 A3 / 8D / DMAIC 视图
- 多人只读分享（一期用导出文件代替）

## 7. 一期明确不做

- 注册、登录、班级码、账号体系
- 按岗位预置选题或行业包
- 讲师审批闸门、自动打分替代自检
- 企业微信 / 钉钉深度集成
- 完整统计检验与自动根因计算
- 多人实时共编白板
- 知识库问答（先把课题走通，再做检索）
- 统一代管的模型额度（模型由学员自己的 API 承担）
